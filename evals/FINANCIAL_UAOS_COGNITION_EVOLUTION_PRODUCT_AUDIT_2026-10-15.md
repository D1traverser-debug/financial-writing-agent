## Objective
Verify that Financial Writing inherits UAOS cognition and governed-evolution capabilities without becoming a second controller, while retaining independent Financial product/business ownership. Also verify that parent product review converted the Financial feature set into a complete domain product-requirement/architecture/acceptance map.

## Initial findings
1. Financial 0.8.3 declared `adaptive_deliberation_and_parent_guidance` and `governed_self_evolution`, but the then-parent `COMMON_CAPABILITIES` contract still contained older conditional-research and over-strong host-enforcement semantics.
2. Financial 0.8.3 already had a real domain evolution substrate in `owner_lifecycle.py`: material feedback/system-impact records, root-cause layer, generalization scope, alternatives/failure modes, regression/eval plan, evidence refs and maintenance closure requiring at least `REGRESSION_VERIFIED` evidence.
3. Financial maintenance guidance did not yet enforce the current every-problem research+reflection floor.
4. Financial entry/architecture wording could still be read as requiring UAOS routing/delegation for normal work even after direct-child topology was adopted.
5. Financial had architecture documentation and extensive tests/evals but no single current product requirements authority mapping user journeys/functions to owner surfaces and acceptance evidence.

## External method evidence
- Anthropic agent-evaluation guidance: evaluation-driven development makes product requirements concrete and exposes reactive-regression risk.
- OpenAI evaluation guidance: variable AI behavior requires structured, repeatable evals against intended outputs/steps.
- Google SRE incident/postmortem guidance: incidents should generate root-cause/system learning rather than symptom-only repairs.
- Evolutionary-architecture fitness-function guidance: automated architecture checks should continuously enforce meaningful boundaries without binding to incidental implementation prose.
- Google developer-documentation guidance: current documentation should state actual versus required/recommended state precisely; a production authority should not continue to present itself as a candidate.

These sources informed three borrowed properties rather than wholesale framework adoption:
1. product requirements -> executable/observable eval mapping;
2. problem -> root-cause/system learning loop;
3. architecture/authority semantics -> stable fitness checks and current-state documentation.

## Governing assumptions challenged
- Rejected: declaring an inherited capability ID proves current semantic inheritance.
- Rejected: Financial needs a copied UAOS cognition/evolution controller.
- Rejected: every detected problem must become a durable writing rule.
- Rejected: parent-assisted product review transfers Financial business-spec ownership to UAOS.
- Rejected: normal Financial work must traverse a live UAOS router after domain selection.
- Rejected: graders should freeze obsolete exact JSON shapes rather than intended contract behavior.
- Rejected: candidate/version labels may remain in current production product authority after promotion.

## Final architecture
### Parent/common layer
UAOS 2.4.5 / common contract 1.5.0 owns the reusable common method:
- every detected problem -> micro diagnosis + macro/topology alignment + governing-assumption challenge + external research;
- risk adds counterexample/independent evidence depth;
- every problem is evaluated for learning impact, but only evidence-backed scoped candidates are promoted;
- product review fills user outcome, functional/non-functional requirements, workflow/state, failure/recovery, assurance, acceptance/evals, non-goals and ownership boundaries.

### Financial domain layer
Financial owns:
- `docs/product_requirements.md` and `docs/architecture.md`;
- article identity/state/workflow/contracts;
- business rules and writing methods;
- material-feedback/system-impact lifecycle;
- domain regression/eval evidence and domain rule promotion.

Common/cross-domain changes use parent guidance/upcall. No child parent-controller/evolution catalog was introduced.

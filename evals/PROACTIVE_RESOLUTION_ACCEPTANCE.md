# Proactive Resolution Repair — Acceptance Checklist

Candidate acceptance requires:

- Financial maintenance authority points to the proactive-resolution rule and durable problem journal;
- missing highest-tier voice/preference evidence is explicitly not an automatic user blocker;
- the rule requires available-context/durable-evidence recovery before avoidable user escalation;
- provisional candidates preserve scope/confidence/unknowns/validation plan rather than fabricating certainty;
- every encountered problem has a durable journal path, including failed/rejected repair attempts;
- cross-domain implications are recorded as a non-mutating parent handoff, not directly written into UAOS;
- regressions exercise the new rule surfaces;
- full Financial CI passes before promotion;
- production authority is reread after merge.

# 财经写作用户目标逆向推演（2026-11-14）

归属：仅 `financial-writing-agent`，不得修改 CAOS。范围：用户要求的**真实完整写作过程**及成果，而不是外部平台授权七门槛、GitHub CI 数字或签名凭证。

## 一、为什么只有用户提到才发现缺陷

**共享根因：此前工程验收以实现为出发点，而不是以用户的最终成果为反证对象。**

旧测试的“完整十阶段”是模拟：测试宿主自己制造研究源、阶段 JSON、审稿 PASS、合成 Word 和页图。它证明状态机拒绝未授权提交和损坏文件，却不能推导“研究、反证、决策、写作、独立审校等真实能力已执行”。每次按新反馈追加一个局部守卫，仍不能保证**用户要求—研究证据—选择论点—两种文章—四份成品—用户验收**跨界无缝。

本轮先冻结 `docs/product_requirements.md` 的 19 项用户成果义务，分别给出测试出处与未证实的真实结果；生成 `evals/FINANCIAL_GOAL_FIRST_REQUIREMENT_MATRIX_20261114.json` 并纳入代码测试。之后任一新增 PR 要求而不填反证矩阵，将导致 CI 失败。每个结果保持 ENGINEERING 或 OPEN，不能把合成通过偷换为用户接受。

## 二、逆向逐项追责

从最后一份 Word 开始向后追问：

1. **读者有所得吗？** 标题是否兑现，前几句是否吸引合适人群，各节是否增量信息/公司因果，结尾有没有回报，是否自然、不像流水账？目前只有历史拒稿反例与结构报警，没有新稿独立实测。
2. **Deep/Broad 是否真实不同？** 已能拒绝相同结构与相同 Word 核心正文，但仅换局部同义词仍可能逃脱，读者旅程不同须进一步语义审稿。
3. **成品是否符合原始用户指令？** 之前 `task_publication.py` 用唯一 Deep 特定要求的白名单，任何新 `ALL`、`FINANCE_BROAD` 或普通 Deep 的要求都会在 Word 构建阶段被判为“未知不得通过”，与 `TaskRequirement Authority` 可记录开放要求直接矛盾。此次改为逐项核对当前 owner 阶段要求满足证据与 digest，不再因 ID 未硬编码造成死锁；语义正确性仍明确 OPEN。
4. **文章要用的来源和信息真实充分吗？** Source Trace 验证快照哈希、数值单位与部分方向冲突，不足以证明关键陈述及因果。真实行业公司池、及时信息和事实含义仍须逐项查证，不能把 SHA 当成事实。
5. **是否真的进行每一步研究、反证和推演？** `writing_kernel.py` 曾只定义 13 步任务及 DAG，`validate_kernel` 只检环和节点。根本不检查生产者—消费者字段是否衔接。发现 RESEARCH_DISCOVERY 未产生后续 RESEARCH_ADVERSARIAL 所需 discovery_package，反证未产生 SYNTHESIS 所需 adversarial_package，THESIS_ADJUDICATION 反而要求预先提供 decision_envelope。此次统一输入输出契约，增加 `validate_pass_dataflow`，并在 `execute_writing_passes` 中实际按依赖调用各 pass callback，在研究裁决与故事架构之间强制经过 Research Audit；缺源、缺任意中间产物、审查失败立即停止，不生成虚假的下游 PASS。
6. **改要求之后是否复核旧工作？** Owner 当前已有 task-revision/invalidation 路由，新增场景用 `ALL` 要求分别作用于 RESEARCH、TITLE、DRAFT、DELIVERY，检查能到 Word 前且没有提前“语义满足”；离开 DELIVERY 缺要求满足收据时必须失败。

## 三、反例驱动的交叉场景

| 场景 | 预期结果 | 本轮新增/复用验证 |
|---|---|---|
| 用户一句话要求完整财经文章 | 必须按实际输入—输出执行所有 pass；不能以 DAG 代替跑通 | 13 步 executor 测试，真实 LLM 仍 OPEN |
| 上游研究做了却没有 discovery_package | 反证不得继续、更不得写稿 | pass 输出契约缺失反例 |
| 研究审查只给 PASS，没有证据 | 不得走到 STORY_ARCHITECTURE | Research Audit boundary 反例 |
| 正文金融事实审查异常 | 不得进入 FINAL_SYNTHESIS | 审查回调失败反例 |
| 用户要求两篇都讲特定经济问题 | RESEARCH/TITLE/DRAFT/DELIVERY 中任一阶段都不应被白名单误杀 | 四个 affected_stage 参数化测试 |
| 同一用户要求尚未到执行阶段 | 不可提前宣布满足 | 任务要求 pending 反例 |
| 交付阶段要求只在 Word 生成后检查 | 构建时显式 PENDING，最终转换缺收据必须失败 | DELIVERY 两段式原子转换反例 |
| Deep 和 Broad 同标题结构/相同正文 | 不能只改标题绕过 | 既有策划与 Word 正文双层反例 |
| 海风拒稿机械堆章节、金红石无相同结构 | 检出真实负样本，不误伤跨题材邻例 | 真实存档回归 |
| 文章修订后来源已过期 | 不得凭原 Word 哈希直接发布 | 研究源时效回归 |

## 四、仍然不能认定达成的用户要求

- 研究：尚未在新用户选题上真实搜证、确认公司池完整性、逐项反证，出具可靠的当前 PrivateResearchBrief。
- 决策：没有当前真实行业数据证明“哪个事件/公司、为何讲、哪个更值关注”的比对结果。
- 写作：`execute_writing_passes` 是宿主调用契约，本身不能启动 LLM 或财务数据库；尚无真实写作执行结果和跨对话可靠性证明。
- 质量：稿件原创、标题吸引力、正文自然、公司经济价值、读者获得感、后续留存没有新的独立读者反馈。
- 交付：真实 Deep/Broad/短内容包/审计四份 Word 尚未因本次修复生成并被用户验收。
- 学习：历史拒稿已固化为诊断用例，但“写新稿→用户评价→归因→跨题材改善”还没有闭环。
- 需求语义：逐阶段证据收据只代表阶段执行，没有确立“稿件真正满足这个自由文本要求”；必须配合源文摘录/文章片段的审稿判断和可核对的用户评价。

### 结论

**实现层的可执行性在改善，真实用户写作目标仍为 NOT_READY。** 本轮新增的是能主动找出“目标—接口—产物”断链的校验方法和实际发现的接口修复，不应再用“CI 绿了”回答“所有用户需求都达成了吗”。

必须在当前金融写作系统中完成一个全新、事实可核验的真实案例，从搜证到四份 Word，再以海风拒稿和跨题材留置稿为反例判卷。只有这样，才能审定真实满足用户写作要求，而不是等用户指出一个缺陷才补一个规则。

## 五、主动暴露当前要求进度，而不是等待用户发现

原来的 `observe_article` 只显示 active requirement ID、阶段与 Word 文件名，无法直接回答“用户原文要求现在落实到了哪里”。此次新增只读投影 `user_goal_progress`：逐项保留原始要求、作用范围、阶段、阶段证据、未完成内容以及始终尚待真实验证的语义/读者接受。用户无需在聊天中重复问一遍要求是否被遗漏。阶段回退后，即使旧历史有 SATISFIED 收据，当前尚未离开的阶段仍显示 DUE，不复用旧通过。

### 实际发现、非测试自证

1. **句级比较映射错误可以穿透数值正确的稿件。** Broad初稿给出正确的三家公司数字，但“分别走出上升、下降和温和增长的路径”与紧邻公司的排列产生错误指代，初次机械检查未发现。真实内容复核后改为“两家增长、一家下降，且增幅差距明显”。这说明字段完整、数值可查、普通出版版式通过，不保证对比句的实体—指标—方向一致。
2. **存量资产与期间流量不应机械比较。** 存货、应收是2026-09-30时点余额并与2025年末比较；营业收入、利润与经营现金是2026年1—9月累计并与去年同期比较。以同期增速拼出直接因果链必须失败。
3. **同一产业链不等于同一商业模式。** 光模块企业与光器件企业生产/采购/客户结算不同；单个经营现金净额除归母净利润的比值不能充当跨公司商业价值排名。
4. **研究选择仍不满足完整覆盖。** 仅三家代表性样本，未完成全材料价值链公司池、所有更晚公告、独立源文原创性比对或用户真实阅读结果。不能将内容层样稿声称为 PrivateResearchBrief 15模块通过。

- ENGINEERING：PR#81已合并至main `890b80a80bb7bb9cd579074f56f566fc4b193374`，post-merge GitHub CI run 43580685186 成功；其保证仅是系统工程合同。
- CONTENT-PILOT：基于真实发行人一手证据生成四份独立的Word样稿并进行可视版式复核；实际发现并修复比较句指代错误。
- OPEN：宿主 `standalone_runtime` 真实模型回调与原子状态迁移、真实公司池研究完备性、跨来源反证、独立编辑质量评价、实际读者接受及跨主题稳定性。

# Maintenance module

New feedback must be classified before changing the system.
- A run-local constraint belongs only to current TaskContract/state.
- A durable writing rule updates its single owner in `config/rule_ownership.json`.
- A platform observation is an experience sample until repeated/current evidence supports a stronger rule.
- If an existing rule was skipped, treat it as a runtime/trajectory defect; do not duplicate it in more files.
- External platform changes require fresh authoritative verification before policy changes.
- Accepted style edits may inform the anti-AI/style library, but one article must not become a rigid template.

## Change protocol
1. Identify rule owner and affected runtime stages.
2. Modify the owner only.
3. Search contradictory/duplicate legacy wording.
4. Add/update regression tests and trajectory assertions.
5. Run unit, static, contract and trajectory tests.
6. Run representative live writing/image-delivery tasks when behavior depends on model/tool execution.
7. Promote only after readback/regression pass.

A documentation edit is not proof that an Agent executes the behavior. Runtime traces, files and audit evidence are proof.

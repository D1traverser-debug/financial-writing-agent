# ChatGPT Site deployment specification — Financial Writing Agent

Any future Site/MCP deployment is capability transport inside the existing UAOS-controlled Financial trajectory. It must not create a second task controller, business-state authority, alternate workflow or fallback runtime.

Current authority:
- controller: `D1traverser-debug/universal-agent-os@main`;
- domain entry: `UAOS_SKILL.md`;
- binding: `.uaos/*`;
- execution contract: `config/EXECUTION_CONTRACT.json`;
- article state: `workspaces/articles/{task_id}/STATE.json`.

Canonical workflow:
`INTAKE -> RESEARCH -> RESEARCH_AUDIT -> EDITORIAL -> TITLE -> DRAFT -> EDITORIAL_AUDIT -> DELIVERY -> MECHANICAL_AUDIT -> FINAL_AUDIT`.

A transport may expose model/web/document capabilities only after current-session permission/capability checks. It may not weaken the business contract or create another durable checkpoint authority.

Do not enable public/workspace/multi-user sharing until tenant isolation, authorization, task/artifact namespace isolation and cross-user access tests exist.
